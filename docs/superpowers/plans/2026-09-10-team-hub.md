# Team Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only, always-on "team wall" that aggregates every teammate's colony and surfaces the sessions that need a human — who, which repo, how long — with a live NEEDS YOU board, a new-attention popup + mutable sound, and a per-colony status strip, running on an Intel NUC in a Linux kiosk.

**Architecture:** Reuse the existing Bot Crossing app in a new **hub mode** (`?hub=1`): it adds every teammate as a neighbour so its own `/api/threads` already returns everyone's threads merged and colony-tagged, renders the colony game dimmed as a backdrop, and draws a triage HUD on top. Two foundation fixes land first (they improve every install): infer liveness from a fresh transcript when the CLI live-process file is absent, and give a folder-less session its own zone named by its title. A small `allowedReaders` addition lets each teammate allow the hub without the hub appearing as a dead colony on their map.

**Tech Stack:** Node 22 (ESM, `node:test`), Vite, three.js (existing); plain DOM + CSS for the HUD; Chromium kiosk + systemd on Linux for the NUC.

**Spec:** `docs/superpowers/specs/2026-09-10-team-hub-design.md`

## Global Constraints

- **Node:** `>=22.13`. Build/test with the repo's Node 22 (`C:\Users\dimx\AppData\Roaming\nvm\v22.23.2\node.exe` on the dev machine).
- **UI language:** English (matches the existing app and keeps upstream merges clean).
- **Read-only is structural:** hub mode must expose no action that writes to anyone's harness — open/archive/new-conversation/share controls are absent, not merely disabled.
- **No new runtime dependencies.** Plain DOM/CSS/Web Audio; no frameworks.
- **Tests:** `node --test "test/**/*.test.mjs"`. Pure logic is TDD'd; DOM/3D and the kiosk launcher are implement-and-verify (the repo has no DOM test harness — do not add one).
- **Branch:** `team-hub` (already created, spec committed there).

```javascript
/**
 * How recently a transcript must have been written to count a session as live when no CLI
 * live-process file exists. Desktop-app / Agent-SDK sessions do not write that file, so their
 * work would otherwise read as idle; a transcript touched this recently is the honest signal.
 */
const LIVE_TRANSCRIPT_MS = 45 * 1000

/** A session is working now if it has a live pid, or its transcript was just written. */
export function isSessionActive({ hasLiveProcess, transcriptMtime, now = Date.now() }) {
  if (hasLiveProcess) return true
  return typeof transcriptMtime === 'number' && now - transcriptMtime < LIVE_TRANSCRIPT_MS
}
```

```javascript
import { statusFor } from '../game/colony.js'

/** Threads that need a human, worst-waited first. Pure — no DOM, no clock beyond `now`. */
export function triageRows(threads, now = Date.now()) {
  const out = []
  for (const t of threads || []) {
    const status = statusFor(t, now)
    if (status !== 'waiting' && status !== 'blocked') continue
    out.push({
      id: t.id,
      colony: t.colony || '',
      project: t.colony ? String(t.project || '').replace(`${t.colony} · `, '') : t.project || '',
      title: t.title || 'Untitled thread',
      status,
      waitMs: Math.max(0, now - (t.lastActivityAt || now)),
    })
  }
  return out.sort((a, b) => b.waitMs - a.waitMs)
}

/** Ids in `rows` that were not in the previous attention set — the popup triggers. */
export function newlyNeedsAttention(prevIds, rows) {
  const prev = prevIds instanceof Set ? prevIds : new Set(prevIds || [])
  return rows.filter((r) => !prev.has(r.id)).map((r) => r.id)
}
```
